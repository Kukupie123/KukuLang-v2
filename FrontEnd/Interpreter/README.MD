# KukuLang Interpreter 🏃‍♂️

The **Interpreter** is the final stage of the runtime. It takes the **Abstract Syntax Tree (AST)** generated by the Parser and executes it instruction by instruction.

## Architecture: Tree-Walking

KukuLang uses a **Tree-Walking Interpreter**. This means it traverses the AST nodes recursively, executing actions as it visits each node. This is implemented via the `MainInterpreter` class which initializes the global state and then delegates to the `StatementProcessor`.

### 1. MainInterpreter Entry Point
The `MainInterpreter.cs` file is the captain of the ship.
1.  **Initialize Types**: It reads all `CustomTypes` from the AST and registers them in the Global Scope.
2.  **Initialize Tasks**: It registers all `CustomTasks` (functions) so they can be called.
3.  **Global Runtime Scope**: It creates `RuntimeScope` (the memory of the running program).
4.  **Execution Loop**:
    ```csharp
    // MainInterpreter.cs
    ASTRootScope.Statements.ForEach(statement =>
    {
        // Skip return statements at the global level
        if (statement is ReturnStmt) return;
        
        // Execute the statement
        StatementProcessor.ProcessStatement(statement, runtimeRootScope);
    });
    ```

### 2. Runtime Scope (`RuntimeScope`)
This is the "Environment" or "Stack Frame". A `RuntimeScope` holds:
-   `DeclaredTypes`: Struct definitions available here.
-   `DeclaredTasks`: Function definitions available here.
-   `CreatedObjects`: **Variables** (e.g., `a = 10`).

**Scope Resolution:**
When the code asks for a variable `x`:
1.  Check current scope.
2.  If not found, check `ParentScope`.
3.  Repeat until Global Scope is reached or error is thrown.

### 3. Statement Processor
This is the workhorse. Similar to the Parser's evaluator, it switches on the Statement Type to decide what to do.

-   **`EvaluateSetTo`**:
    1.  Evaluates the Right-Hand Side (RHS) expression to get a `RuntimeObj` (Value).
    2.  Resolves the Left-Hand Side (LHS) variable name.
    3.  Updates the `CreatedObjects` dictionary in the correct scope.

-   **`EvaluateIf`**:
    1.  Evaluates the condition expression.
    2.  If true, it creates a **New Scope** (child of current).
    3.  Executes the list of statements in the `Then` block.
    4.  Disposes the scope (simulating stack popping).

-   **`EvaluateFunctionCall`**:
    1.  Finds the `CustomTask` by name.
    2.  Evaluates all arguments passed in.
    3.  Creates a **New Scope** for the function body.
    4.  Maps argument values to parameter names in that new scope.
    5.  Executes the function body.

---

## Runtime Objects (`RuntimeObj`)
Every value in KukuLang (whether a number, text, or complex struct) is wrapped in a `RuntimeObj` during execution.
- **Primitive Values**: Simply hold the C# equivalent (`int`, `string`, `bool`).
- **Custom Structures**: Hold a `Dictionary<string, RuntimeObj>` mimicking a property set.

---

## Comparison with Compilers
Unlike a Compiler which translates source code into machine code (binary) or bytecode (like Java's `.class`), an Interpreter executes the logic **directly**.
- **Pros**: Easier to implement, easier to debug, instant startup.
- **Cons**: Generally slower than compiled code for heavy computation.

## Execution Flow Example

**Code:**
```kuku
set a to 10;
if a is 10 then {
    print with "Ten";
}
```

**Interpreter Actions:**
1.  **Visit `SetStatement`**:
    -   Create `RuntimeObj(10)`.
    -   Store it in Current Scope with key `"a"`.
2.  **Visit `IfStatement`**:
    -   **Evaluate Condition**: Look up `"a"` (finds 10). Check `10 == 10`. Result: `True`.
    -   **Enter `Then` Block**: Create new Scope (Parent = Global).
    -   **Visit `FunctionCall (print)`**:
        -   Resolve `print` (Built-in).
        -   Execute: Write "Ten" to Console.
    -   **Exit Block**: Dispose Scope.
